# Техническая спецификация платформы интеллектуальной визуализации данных

## 1. Цели и ключевые сценарии использования
- **Целевая аудитория:** менеджеры без технического бэкграунда и бизнес-аналитики с базовыми навыками.
- **Основная задача:** автоматизировать импорт данных по продажам, маркетингу и финансам, выполнять интеллектуальную классификацию, аналитическую обработку и генерировать визуализации и рекомендации без участия технических специалистов.
- **Ключевые сценарии:**
  1. Загрузка CSV-файла с продажами и получение круговых диаграмм, динамики продаж и рекомендаций по промо.
  2. Загрузка Excel-отчёта по финансам с автоматической генерацией линейных графиков, прогнозов и советов по оптимизации расходов.
  3. Загрузка JSON с маркетинговыми метриками и построение интерактивного дашборда (воронки, тепловые карты) с рекомендациями по каналам трафика.
  4. Просмотр истории визуализаций, скачивание отчётов и отслеживание выполнения рекомендаций.

## 2. Общая архитектура
Архитектура разделена на три основных слоя:

### 2.1 Клиентский слой (Frontend)
- **Фреймворк:** React (TypeScript) с модульной архитектурой и React Query для взаимодействия с API.
- **Библиотеки визуализации:**
  - Plotly.js для интерактивных дашбордов и комбинированных графиков.
  - Chart.js через обёртку `react-chartjs-2` для круговых и линейных диаграмм.
  - D3.js для специализированных визуализаций (воронки, тепловые карты).
- **UI-библиотека:** Ant Design или Vuetify (при выборе Vue) для ускорения разработки и обеспечения доступности.
- **Состояние:** глобальное через Zustand/Redux Toolkit; локальное состояние компонентов — React useState/useReducer.
- **Возможности клиента:** загрузка файлов (drag-and-drop), предпросмотр данных, выбор рекомендованных метрик, интерактивная панель инсайтов и рекомендации с чек-листом выполнения.

### 2.2 Сервер приложений (Backend API)
- **Стек:** Node.js (NestJS) для управления HTTP API, авторизации и оркестрации задач; Python-сервисы для аналитики и ML.
- **API:** REST + WebSocket (для прогресса обработки).
- **Сервис-ориентированная архитектура:**
  - `ingestion-service` (Node.js) — валидация, временное хранение данных, передача в аналитический пайплайн.
  - `classification-service` (Python/FastAPI) — определение типа данных.
  - `analytics-service` (Python/FastAPI) — статистический анализ, выявление трендов, аномалий, прогнозирование.
  - `recommendation-service` (Python/FastAPI) — генерация текстовых советов и приоритизация.
  - `rendering-service` (Node.js) — подготовка конфигураций визуализаций для фронтенда, экспорт PNG/PDF (через headless Chrome/puppeteer).
- **Обмен данными:** брокер сообщений (RabbitMQ) для постановки задач обработки и очередей ML, Redis для кэширования промежуточных результатов и сессий.

### 2.3 Хранилище и управление данными
- **Временное файловое хранилище:** AWS S3/GCS или локальный MinIO с автоматическим TTL (например, 24 часа).
- **Метаданные и результаты анализа:** PostgreSQL (таблицы пользователей, загруженные наборы, результаты классификации, инсайты, рекомендации, статусы выполнения).
- **История визуализаций и отчётов:** сохранение в базе с ссылкой на файлы PNG/PDF в хранилище.

## 3. Потоки данных
1. Пользователь загружает файл через drag-and-drop.
2. Frontend отправляет файл на `ingestion-service` (multipart upload), который сохраняет его во временном хранилище, проверяет формат и размер.
3. `ingestion-service` публикует задачу в очередь `classification`. Python-сервис извлекает задачу, анализирует колонки и структуру, присваивает тип данных (продажи, маркетинг, финансы) и определяет потенциальные метрики.
4. Результат классификации возвращается в PostgreSQL и уведомляет фронтенд через WebSocket.
5. На основе типа данных формируется аналитический пайплайн: запуск трендового анализа, корреляций, аномалий, прогнозов, сегментаций.
6. `analytics-service` записывает результаты в базу и передаёт ключевые показатели в `recommendation-service`.
7. Модуль рекомендаций генерирует текстовые советы и ранжирует их по влиянию/усилиям, записывает в БД.
8. `rendering-service` формирует конфигурации визуализаций (JSON) и, при необходимости, готовит статические изображения.
9. Frontend через REST/WebSocket получает конфигурации, инсайты, рекомендации и отображает их в UI.
10. Пользователь может экспортировать отчёт — фронтенд отправляет запрос на генерацию PDF/PNG, результат скачивается.

## 4. Обработка и классификация данных
- **Парсинг файлов:**
  - CSV: `pandas.read_csv` с автоматическим определением кодировки (chardet) и разделителя.
  - Excel: `pandas.read_excel`, поддержка нескольких листов с выбором пользователем.
  - JSON: валидация схемы и нормализация в табличный формат.
- **Классификация:**
  - Лексический анализ заголовков столбцов (словарь ключевых слов на нескольких языках, нормализация регистра, стемминг).
  - Статистические признаки: распределение значений, числовые/категориальные типы, наличие временных меток, валютных форматов.
  - Модель ML (например, RandomForest или LightGBM) обученная на признаках датасета (TF-IDF по названиям колонок + числовые статистики).
  - Правила приоритета: если есть >60% совпадений по словарю продаж — тип «продажи»; при конфликте — комбинированный тип, что влияет на выбор визуализаций.
- **Определение метрик:** шаблоны для расчёта KPI по каждому типу данных (продажи, маркетинг, финансы) с автоматическим маппингом колонок (например, колонка `revenue` → метрика «Общий объём продаж»).

## 5. Аналитический модуль
- **Тренды:** STL decomposition, seasonal ARIMA/Prophet для временных рядов.
- **Аномалии:** Isolation Forest, z-score, Twitter Anomaly Detection (ADVec) в зависимости от объёма данных.
- **Корреляции:** Pearson/Spearman, визуализация тепловых карт.
- **Сегментация:** кластеризация K-Means/DBSCAN по продуктам или каналам трафика; построение вкладов сегментов.
- **Сравнения:** автоматическое сопоставление с предыдущими периодами (последний аналогичный период) и бенчмарками (хардкод или импорт отраслевых данных).
- **Прогнозирование:** Prophet/LSTM (для длинных рядов) с оценкой доверительных интервалов.
- **Причинно-следственный анализ:** Granger causality, линейные регрессии, uplift-анализ для маркетинговых кампаний.

## 6. Движок рекомендаций
- **Вход:** результаты аналитики (метрики, тренды, аномалии) и классификация типа данных.
- **Алгоритм:**
  - Создание базы правил (rule engine) с триггерами (например, «падающий тренд продаж > 10% за 2 периода» → рекомендация «запустить промо»).
  - Использование NLP-модели (GPT-2/Flan-T5, fine-tuned) для генерации естественного языка на основе шаблонов и структурированных данных.
  - Оценка воздействия: `impact_score` рассчитывается по историческим данным и степени отклонения от бенчмарков.
  - Оценка усилий: `effort_score` на основе классификации действий (быстрая кампания, переработка сайта, изменение бюджета и т.д.).
  - Приоритизация: сортировка по матрице «влияние/усилия», отображение категорий (High Impact/Low Effort и т.д.).
- **Выход:** JSON-структура карточки рекомендации (заголовок, описание, ожидаемый результат, KPI, impact/effort).

## 7. Генератор визуализаций
- **Правила выбора визуализаций:**
  - Продажи → круговые диаграммы по продуктам/категориям, столбчатые графики динамики, KPI-панель.
  - Маркетинг → воронка конверсии (D3), тепловые карты по каналам (Plotly Heatmap), линейные графики CTR/CPC.
  - Финансы → линейные графики доходов/расходов, area charts маржинальности, waterfall для анализа отклонений.
  - Комбинированные наборы → интерактивные дашборды с несколькими виджетами.
- **Конфигурации:** описываются JSON-схемами (например, `VisualizationConfig`), включающими источник данных, тип графика, отображаемые поля, стили.
- **Кастомизация:** пользователь может менять цвета (предустановленные палитры), подписи, интервалы агрегирования (день/неделя/месяц), сортировку.
- **Экспорт:** серверная рендеринг через `puppeteer` + Plotly static image export, генерация PDF отчётов (ReportLab/WeasyPrint).

## 8. UI/UX дизайн
- **Главная панель:** карточка загрузки (drag-and-drop), история наборов, быстрые ссылки на шаблоны.
- **Мастер визуализации:** шаги — загрузка → классификация (показать «Обнаружены данные по продажам») → выбор метрик → просмотр графиков → экспорт/сохранение.
- **Панель метрик:** плитки с рекомендованными KPI (чекбоксы), возможность добавить собственную метрику (выбор колонки и агрегата).
- **Дашборд визуализаций:** вкладки по типам графиков, превью-иконки, пояснения простым языком.
- **Инсайты:** раздел с иконками важности, карточки с текстом, выделение аномалий цветом.
- **Рекомендации:** карточки с impact/effort, чекбоксы «выполнено/отложено», индикатор прогресса.
- **Контекстная помощь:** тултипы, walkthrough, FAQ.
- **Адаптация:** responsive дизайн, поддержка планшетов.

## 9. Безопасность и соответствие требованиям
- Ограничение размера файла (например, 50 МБ) с проверкой на стороне клиента и сервера.
- Валидация формата и структуры (отклонение несоответствующих MIME-типов).
- Очистка данных, защита от CSV Injection.
- HTTPS, JWT-аутентификация, ротация токенов.
- Хранение данных с TTL, автоматическое удаление при завершении сессии, возможность ручного удаления пользователем.
- Логирование действий и аудиторский след.

## 10. Нефункциональные требования
- **Производительность:** обработка набора данных до 100 тыс. строк < 30 секунд; асинхронная обработка с отображением прогресса.
- **Масштабируемость:** горизонтальное масштабирование сервисов через Kubernetes; автоскейлинг аналитических воркеров.
- **Надёжность:** retry-механизмы в очередях, мониторинг (Prometheus + Grafana), алёртинг (PagerDuty).
- **Локализация:** поддержка мультиязычности (RU/EN) для интерфейса и рекомендаций.
- **Доступность:** соответствие WCAG 2.1 AA (контраст, фокус, альтернативный текст).

## 11. План разработки и развертывания
1. **MVP (спринты 1-3):** загрузка файлов, классификация, базовые визуализации по типам данных, простые текстовые рекомендации.
2. **Расширение аналитики (спринты 4-6):** аномалии, тренды, прогнозы, сегментация, улучшение генератора рекомендаций.
3. **Улучшение UX (спринты 7-8):** мастер визуализаций, история, экспорт, настройки графиков.
4. **Оптимизация и масштабирование (спринты 9-10):** отказоустойчивость, мониторинг, безопасность, локализация.

## 12. Технологический стек и DevOps
- **CI/CD:** GitHub Actions + Docker + Kubernetes (Helm charts).
- **Инфраструктура:** Terraform для управления облачными ресурсами, секреты в HashiCorp Vault.
- **Качество:** линтеры (ESLint, Prettier, Flake8, Black), тесты (Jest, React Testing Library, PyTest), e2e (Cypress).
- **Наблюдаемость:** централизованные логи (ELK/EFK), трассировка (Jaeger), метрики (Prometheus).

## 13. Открытые вопросы и риски
- Точность классификации комбинированных наборов данных — требуется A/B тестирование и ручная корректировка.
- Подготовка и поддержка словарей ключевых слов на разных языках.
- Сложность интерпретации рекомендаций пользователями — нужен пользовательский ресёрч и UX-тестирование.
- Обработка очень больших Excel-файлов — возможно внедрение chunk-парсинга и стриминговой обработки.
- Управление конфиденциальными данными — рассмотреть опцию on-premises развёртывания.
